# ASSUMPTIONS

Every gap was resolved with the safest standard default. Items marked **[review]** appear in `REVIEW.md` decisions for post-delivery review.

| ID | Question we would have asked | Assumption | Impact if wrong | Status |
|---|---|---|---|---|
| A-001 | Must the first-run demo work offline with no server install? | The app is a full-stack web app; “no signup” means an anonymous server-backed guest session, not a static-only app. Offline read/capture is supported after first load. **[review]** | A fully peer-to-peer/local-only expectation would need a different sync architecture. | Accepted |
| A-002 | Which database should replace PostgreSQL when Docker is unavailable? | Prisma + SQLite for local/CI. Schema and tenant queries avoid SQLite-only SQL; PostgreSQL migration path documented. **[review]** | Scale target 10k users requires PostgreSQL and horizontal app instances. | Accepted |
| A-003 | Which email provider? | SMTP via Nodemailer when `SMTP_URL` is set; otherwise a persisted development outbox and visible magic link/digest preview. Production must configure SMTP. | No real email delivery in zero-config mode; documented. | Accepted |
| A-004 | Which OAuth providers can actually be activated? | Google and GitHub self-serve OAuth when env credentials are set. Apple is represented in provider configuration/docs but hidden unless credentials exist. Buttons are disabled with explanation rather than fake. **[review]** | Apple sign-in requires an Apple developer account. | Accepted |
| A-005 | Which SSO protocol? | OIDC authorization-code + PKCE, discovered via issuer metadata. SAML is backlog. | Enterprise buyers needing SAML-only IdPs need the backlog item. | Accepted |
| A-006 | What is an org? | A workspace with `type=org`; team is collaboration with lighter chrome; personal is the default. A team can be upgraded to org by its owner. | Buyer taxonomy may differ. | Accepted |
| A-007 | Who can access enterprise admin? | OWNER and ADMIN; audit visible to them, hidden in personal/team UI. Audit is still recorded for personal actions internally. | Privacy expectation about hidden personal audit may differ. | Accepted |
| A-008 | What does “solo data never exposed to org” mean operationally? | Objects always belong to exactly one workspace. There is no cross-workspace copy except an explicit user-triggered duplicate/move action. Moves between workspaces are not implemented. | Some users may expect explicit task transfer. | Accepted |
| A-009 | Default timezone and locale. | `Intl.DateTimeFormat().resolvedOptions()` on first use; stored on UserSettings; all timestamps UTC. | Server-only clients need explicit timezone. | Accepted |
| A-010 | Capacity definition for Today. | Default 5 hours/day of task estimates, configurable. Calendar inputs are tasks with start/due times because external calendar sync requires credentials. **[review]** | Real external calendar blocking is backlog. | Accepted |
| A-011 | AI provider and data boundary. | AI is local heuristic assistance only in v1 (no outbound customer data); controlled by workspace flag and kill switch. External model adapters are backlog. **[review]** | Brief asks for AI governance; delivered and app works with AI off. | Accepted |
| A-012 | Reminder delivery. | In-app notifications and email outbox. A `jobs` command dispatches due reminders/digests; cron documented. Serverless deployment needs external scheduler. | Reminders don’t fire without a scheduler. | Accepted |
| A-013 | Full-text search engine. | Indexed SQLite FTS5 for task search, with LIKE fallback. PostgreSQL deployment should switch to `tsvector`. | Very large corpora need dedicated search. | Accepted |
| A-014 | Attachments storage. | Local filesystem under `data/uploads` with size/MIME allowlist, auth-checked download, randomized storage name. Production should use object storage + malware scanning. **[review]** | Not compliant for regulated upload workloads. | Accepted |
| A-015 | Encryption at rest. | Application-layer encryption for SSO secrets and TOTP seeds; database-at-rest relies on the host’s encrypted disk/managed database. | Does not satisfy buyers demanding field-level encryption of all content. | Accepted |
| A-016 | CSP strength. | Concrete CSP header with `unsafe-inline` permitted for style/script bootstrap due to Next.js inline bootstrap; no third-party script origins. Nonce hardening is a follow-up. **[review]** | A strict security review may require nonces/hashes. | Accepted |
| A-017 | Rate limiting store. | In-memory fixed-window limiter adequate for single-node demo. Production needs shared Redis/store. | Multi-instance bypass. | Accepted |
| A-018 | Data retention default. | 30-day trash retention; audit 365 days; account deletion anonymizes immediately and purges content. Org admins can set 7–3650 days. | Legal review may change defaults. | Accepted |
| A-019 | “Delete account” semantics. | User may export first; deletion requires typing `DELETE`, ends sessions, deletes memberships and personally owned content, pseudonymizes audit. Personal workspace deleted. | Shared board content owned by org is not removed. | Accepted |
| A-020 | Enterprise procurement artifacts format. | Markdown responses modeled on security questionnaires/VPAT; not certified legal documents. | Legal must review before submission to a customer. | Accepted |
| A-021 | SSO MFA enforcement. | `requireMfa` blocks org use until the member has verified TOTP in the current account; it is not a guarantee about every future session unless login enforces TOTP (it does). | OIDC IdP group policy may be preferred. | Accepted |
| A-022 | Team guest role. | Guest is read-only. Members can edit content; admins manage membership/policy; owner is unique and cannot be removed. | Some agencies expect guest commenting; guests can comment in this v1? No — read-only. | Accepted |
| A-023 | Board templates. | Built-in templates (Personal week, Project sprint, Content calendar) clone into a real board. No marketplace in v1. | Enterprise template governance is backlog. | Accepted |
| A-024 | WIP limit behavior. | Advisory by default: warns but allows move; column can be configured to enforce, returning `WIP_LIMIT` 409. | Product may prefer advisory only. | Accepted |
| A-025 | Idempotency. | Mutations accept `Idempotency-Key`; replay stored for 24h when present. Generated by client for offline/retry paths. | Third-party clients must provide keys for safe retry. | Accepted |
| A-026 | Browser support. | Latest two evergreen versions, responsive down to 360px. No IE. | Legacy enterprise browser needs unsupported. | Accepted |
| A-027 | Localization. | English UI, externalized dictionary and locale-aware date/number formatting; RTL CSS logical properties ready. Full translation backlog. | International buyer may need more locales. | Accepted |
| A-028 | “100% keyboard” scope. | All app flows, including date pickers and DnD, have keyboard paths; native browser file pickers and OAuth redirect away are exempt. | Some platform dialogs are outside page control. | Accepted |
| A-029 | Screenshot/demo credentials. | A deterministic demo account seeded only when `SEED_DEMO=true`; credentials documented and never used on production paths. | Demo data may be disabled in production. | Accepted |
| A-030 | Error tracking vendor. | Structured logs + a captured client error endpoint by default; Sentry adapter documented but not bundled to avoid a secret. | Production observability requires wiring. | Accepted |
| A-031 | Docker availability in this environment. | Docker is not installed here. Dockerfile/compose are delivered and syntax-reviewed, but running them is **unverified**. | Image may need adjustment on the target host. | Accepted |
| A-032 | Lighthouse measurement. | Run against production Next server, localhost; mobile emulation. Browser availability may limit automation; results recorded with caveat. | Field metrics differ from lab. | Accepted |
| A-033 | CalDAV/Google Calendar two-way sync. | Internal calendar + ICS subscription delivered; two-way provider sync is backlog. | Should-deliver “calendar sync/ICS” is met through ICS, not bi-directional sync. | Accepted |
| A-034 | Slack/Teams format. | Generic incoming webhook with Slack-compatible payload; configured by admin. Teams requires its workflow URL and receives an Adaptive Card payload. | Teams connector schema may evolve. | Accepted |
| A-035 | File import limits. | 1,000 tasks / 5 MB per import; attachments not imported via CSV. | Large migrations need a bulk importer. | Accepted |
| A-036 | Public board sharing. | Read-only token URL; passwords/expiry are backlog. Un-sharing invalidates immediately. | Public link is unguessable but not password-protected. | Accepted |
| A-037 | Email digest schedule. | Daily 08:00 in the user’s timezone via `jobs`; user can disable and set quiet hours. | Scheduler must run every 15 min. | Accepted |
| A-038 | AI feature flags. | Per-workspace `aiEnabled` plus global `AI_KILL_SWITCH`; no network calls. | “AI” is assistive deterministic logic, not an LLM in v1. | Accepted |
| A-039 | Pty/Windows filename handling. | Cross-platform paths; attachment names sanitized. | Host-specific path issues possible. | Accepted |
| A-040 | Currency/cost. | AI cost cap documented; current local heuristics incur zero inference cost. | Not meaningful until external provider exists. | Accepted |
